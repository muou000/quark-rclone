# Listing Latency And Directory Pre-cache

首版盘符在"点开一个文件夹要等"这一点上体验很差。慢的原因有两层，分别属于两个进程：

- **适配层**：`GET /file/sort` 一页 100 条，原先严格串行——一个 500 条的文件夹要付 5 个往返，一个 2000 条的文件夹要付 20 个。这是首开延迟的主要来源。
- **挂载层**：rclone 的目录缓存默认 5 分钟，且挂载后不会主动预热。半小时内没再进过的文件夹，第二次点开仍要重新列一遍。

本文记录针对这两层的固定参数（issue 待补）。它不改变 ADR 0002 的写缓存与失败语义，也不改变 ADR 0011 的实例缓存目录布局。

## 适配层：首页串行，余页并行

`Client.List` 先单独取第 1 页，因为只有它带 `metadata._total`，而且单页目录（最常见的情况）不该为一个不会发生的并行付代价。拿到总页数后，第 2..N 页交给固定 8 个 worker 的池子并发拉取。

- **合并顺序按页号**，不按完成顺序。列表结果与并发调度无关，同一目录两次列举顺序一致。
- **并发上限 8** 是礼貌值而非性能上限：Quark 是逆向私有接口，一次点击不该给账号制造突发压力。8 个并发已把百页文件夹的墙钟从"页数 × 往返"压到"少量往返"。
- **任一页失败即取消其余页**。一次失败的列举不该在后台继续烧请求，否则错误处理本身会变成限流事件。
- **`_total` 缺失时退回串行**：provider 不报总数时，只能靠"短页"判断结束，猜页数要么截断要么过量请求。
- **`_total` 当作提示而非承诺**：若按总数算出的最后一页仍是满页，说明总数少报了，继续逐页取到短页为止。少报的总数会截断列表，而截断的列表与"文件夹真的少了文件"在用户眼里没有区别——这正是本项目要避免的误判。
- **按 FID 去重**。并发分页假定 provider 的排序在页与页之间稳定；一旦不稳定，同一 FID 可能落在两页上，而另一个条目被跳过。重复项在本层无害，但下游 WebDAV 层按名字建目录映射，重复项会静默覆盖同名条目、让列表少一个。以 FID（provider 唯一保证的稳定标识）折叠重复项，列表宽度就等于实际观测到的条目数。

并发分页依赖 provider 的排序在页与页之间稳定。这一点**未经真机验证**，见"未决"。

## 挂载层：三个固定参数

`rcloneArgs` 固定传入三个参数，它们不是 profile 字段——它们描述"本客户端希望 rclone 怎么工作"，而不是用户偏好：

| 参数 | 值 | 作用 | 风险 |
|---|---|---|---|
| `--dir-cache-time` | `30m` | 半小时内重进的文件夹直接命中内存中的目录缓存，不再往返 | 绕过挂载的外部变更最多滞后 30 分钟可见；经挂载自身的写入仍立即失效 |
| `--vfs-refresh` | 开 | 挂载可用后**后台**递归预热整棵目录树，首次点击也是热的 | 纯内存（只填目录缓存，不下载文件数据）；rclone 自己控制遍历节奏，不阻塞使用 |
| `--vfs-cache-max-size` | `1G` | 给磁盘文件缓存封顶 | 只淘汰 clean 项；dirty 项 rclone 永不淘汰，ADR 0002 的数据安全约束不变 |

`--vfs-refresh` 的时机很关键：rclone 在 `New` 末尾以 `go vfs.refresh()` 启动它，即挂载已可用之后，因此它不会拖慢挂载完成，也不会阻塞第一次点击。它遍历的是目录树而非文件内容，所以不产生下载流量。

## 与 ADR 0002 / 0011 的关系

- 写路径不变：仍是 `vfs-cache-mode writes` + 实例独占 `--cache-dir`。新参数只加缓存容量上限与 TTL，不触碰回写、dirty 保留、失败记录。
- `1G` 上限只作用于 clean 缓存。ADR 0002 的"dirty cache 在用户清理前不自动删除"因此仍然成立。
- 实例目录布局不变，仍然跨重启稳定，dirty 回写仍可恢复。

## 未决

- **排序稳定性**：并发分页假定同一目录的 `_sort` 在相邻请求间返回稳定顺序。若 Quark 对空 `_sort` 采用非唯一默认排序，页边界可能漂移，导致条目重复或遗漏。这一点只能真机验证，已记录为待查项；在验证之前，8 并发的收益按"可能牺牲少量确定性"对待。
- **`_sort=` 空值与缺省的差异**：本仓库参考实现（vendored AList Quark driver）在排序为 `none` 时**完全省略** `_sort`，本客户端则发送空值 `_sort=`。两者在 provider 侧是否等价未验证。这是与已知可用实现之间唯一的请求形状差异，已记录为待查项。
