# WinFsp Runtime Delivery And Upgrade

首版安装包捆绑匹配版本的官方 WinFsp 安装器，并默认勾选“同时安装 WinFsp”；只有用户明确确认后才启动官方安装器并触发 UAC。应用本身不提权，用户可跳过安装并稍后从托盘修复；未完成安装进入 `WinFspRequired`，需要重启时显示待重启状态但不自动重启。

首版只发布 Windows x64。应用随包分发固定版本、匹配架构的 rclone `rclone.exe`，不读取用户全局 rclone 配置；每次挂载前校验版本和内置 SHA-256 清单，失败则阻止启动并提示修复，不自动下载替换。WinFsp 预检检查架构、注册表安装路径、匹配 DLL、应用声明的最低版本，并执行一次实际挂载自检；失败进入 `WinFspRequired`，不静默升级驱动。

升级使用独立 `Upgrade staging`：先停止挂载并等待盘符消失，再切换应用和 rclone；配置、DPAPI 凭据和独立缓存保留。升级后自检失败时回滚上一版本，禁止新旧挂载进程并行。构建流程生成第三方许可清单和原始许可证文本，中文关于页面和安装目录展示组件版本、来源与许可；WinFsp 官方安装器单独列出。

选择用户确认的官方安装器和 x64 首发，是为了避免应用静默修改系统驱动，同时把验证范围控制在可测试的架构。固定 rclone 与 staging 回滚，则保证挂载行为可复现并避免升级过程损坏 dirty cache。
