# Tray Interaction Model

ADR 0004 规定托盘承担恢复动作，ADR 0010 规定界面使用中文类别与可执行恢复动作。本文记录托盘的实现形态与安全边界（issue #24）。

## 形态：原生托盘 + 本地回环 Web 面板

托盘进程（`quark-tray`）在进程内运行 supervisor 生命周期，界面分两层：

- **托盘图标与菜单**（`fyne.io/systray`，纯 Go，仅依赖已有的 x/sys/dbus）：图标按状态族着色（绿=Mounted、琥珀=启动/恢复、红=暂停待用户、灰=未运行），tooltip 与菜单显示中文状态；菜单项只有「打开主面板 / 重新登录 / 退出」。
- **主面板**（127.0.0.1 随机端口，浏览器打开）：单页三视图——状态（盘符、根目录、中文状态与恢复动作）、诊断（恢复时间线、能力矩阵、回写失败表、脱敏日志与导出）、设置（首配与重认证向导）。全部服务端逻辑在 `internal/trayui`，可单元测试；页面只是渲染。

不引入完整 GUI 框架（walk/wails）：向导需要的是表单与列表，回环页面以零原生代码成本获得全部文本渲染与可测试性；托盘菜单覆盖高频动作，低频流程进面板。程序化生成 ICO（按状态着色），不随包二进制图标资源。

## 状态与文案契约

supervisor 十态与 quarkerr 十四类在 `trayui` 各有唯一中文标签，闭集测试强制新成员必须补文案；每个状态配可执行恢复动作。暂停态（NeedsReauth/DriveConflict/WinFspRequired/Failed）显示「需要处理」，其余自动恢复态显示「将自动重试」——临时错误与永久失败在界面上分流（AC 5）。Copy/覆盖上传的不可用是面板常驻说明，不随错误出现。

## 重新认证契约（AC 3）

向导单一入口 `Apply`：**先验证、后落盘**——候选 Cookie 在一次性会话中验证（失败则不触碰任何持久状态，旧凭据、profile、dirty cache 原样保留）；验证通过才依次持久化凭据（DPAPI）、保存配置（尽力而为，失败不回滚登录）、按 ADR 0004 顺序停止旧挂载并以新凭据重启。重启复用按盘符派生的缓存目录，dirty cache 跨重启续传（ADR 0011）。纯重认证请求不携带任何选项字段，根目录与盘符选择原样保留。

## 安全边界

- 面板只绑 127.0.0.1；每进程随机 token 对**变更类** POST（validate/apply/reauth/recheck）强制校验。token 的作用是阻止本机其它应用在不知道面板地址的情况下**无意**驱动挂载（浏览器 CSRF 形态的误触），它不是对抗恶意本地进程的边界——后者本就能读取页面拿到 token；真正的边界是登录用户的会话本身，与 ADR 0009 的回环端点同一论证。
- Cookie 只进验证逻辑，永不回显到页面、日志或面板数据；候选验证在一次性会话中完成，验证通过后仅持久化「生效 Cookie」。
- 日志在写入边界统一脱敏（`redact.Text`），导出文件即内存环的逐行文本。
- 托盘只支持 profile 模式：无法持久化新凭据的托盘无法兑现重认证承诺。
